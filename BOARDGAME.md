# «Дала дәулеті» — настольная игра QazaqPlay

Казахская экономическая игра для 2–4 участников: люди собираются в комнате,
хост выбирает поле и сценарий, свободные места заполняются ботами.
По умолчанию поле рисуют React/SVG-компоненты поверх WebP-окружения. Клетки
подсвечиваются и увеличиваются при наведении, открываются по клику или касанию.
Фишки и кубики анимируются на клиенте. Дополнительный режим 3D включает Three.js.
Сервер обрабатывает отдельные действия и сохраняет общее состояние комнаты.

Вход «Менің ауылым» открывает постоянный 3D-аул; кнопка «Дала дәулеті» возвращает
к текущему экрану настольной игры. Партия и аул имеют отдельные ресурсы, Telegram-рейтинг
общий. UI использует адаптеры и токены из `web/src/ui-kit/`; витрина компонентов — `/ui-kit`.

## Локальный просмотр

```bash
cd web
npm ci
npm run dev -- --host 127.0.0.1
```

Открыть `http://127.0.0.1:5173/quest`. В обычном браузере доступна автономная
тренировка с ботами: правила исполняются в TypeScript, партия хранится в localStorage.
Она не импортируется в серверный рейтинг. При запрете хранилища игра остаётся в памяти.
После первоначальной загрузки тренировка не обращается к игровому API. Полного
офлайн-кэширования для открытия приложения с нуля нет.

Комнаты с людьми требуют существующую Telegram-авторизацию кинотеатра и работающий
API/PostgreSQL/Redis. Локальный браузерный просмотр не подменяет Telegram-пользователя.
API комнат проверен интеграционными тестами с разными авторизованными участниками.
Работа через настоящий Telegram и сеть между телефонами проверяется после деплоя.

## Подготовленный контент

Единый источник — `web/public/boardgame/catalog.json`. Его читает клиент тренировки,
а сервер проверяет тот же файл при загрузке. Docker-образ бэкенда копирует этот набор
по тому же пути; при изменении нужно обновлять оба образа.
Путь на сервере задаётся `QUEST_BOARD_CATALOG`.

- 2 поля: Алматы и Түркістан; по 40 клеток в классическом порядке.
- 8 сценариев: три варианта длины и режим до последнего игрока для каждого поля.
- 22 улицы в восьми группах (2/3/3/3/3/3/3/2), четыре вокзала, две коммунальные службы.
- Углы: старт, тюрьма/посещение, бесплатная парковка, отправка в тюрьму.
- 12 карточек в двух колодах: Сәттілік и Қазына; налоги 200 и 100 Dala.
- 3 профиля ботов с разным резервом денег для покупки и строительства.
- Четыре дома, затем гостиница. Стартовый капитал 1500, доход за круг 200 Dala.

Фон `art/universe-v1.webp` (~172 КБ) создан встроенным image_gen; промпт хранится
в `art/PROMPT.md`. Две детальные локации — `almaty-v1.webp` и
`turkistan-v1.webp`; их промпты сохранены рядом. SVG-компоненты задают интерактивные
зоны выбора, подсветку, подписи и фишки. Поле плоское, с постоянными
пронумерованными клетками, общими границами и стрелками.
В центре — городская иллюстрация с дорогами, разметкой, зеленью и светофорами.
Новые изображения: `almaty-map-v2.webp` и `turkistan-map-v2.webp`; промпты рядом.
В клетках — увеличенные миниатюры из атласов Алматы и Туркестана.
Специальные клетки используют прозрачный атлас `city-specials-v1.webp` (16 миниатюр):
вокзалы, метро, автобекеты, подстанция, водонапорная башня, тюрьма, парковка,
стартовая арка, киоск карточек, сундук казны и налоговые павильоны.
Промпт: `city-specials-prompt.md`. Это 2.5D-спрайты в том же стиле, что здания.
`CityLife` добавляет машины на дорогах, пешеходов и птиц через SVG animateMotion,
рябь фонтана и смену сигналов светофора — через CSS. При скрытой вкладке и
`prefers-reduced-motion` движущийся слой отключается; игровые клетки не меняются.
Цветовая полоса обозначает группу улиц, отдельный круг с номером — владельца.
Вокзалы нейтральные. Названия улиц реальные;
маршрут остаётся условным игровым. Здания — художественные изображения реальных объектов,
а не точные архитектурные модели. Промпты и источники: [buildings-prompts.md](web/public/boardgame/art/buildings-prompts.md).
Объекты расположены внутри статичных клеток замкнутой дорожки.
Нажатие на объект открывает модальное окно со сведениями, арендой и действиями.
При наведении объект подсвечивается и увеличивается.
Миниатюры — прозрачные спрайты в 2.5D, не вращаемые GLB-модели. Превью локаций используют уменьшенные WebP. Three.js загружается только при выборе 3D или языковой главы.
В 3D используются геометрия, локальные canvas-текстуры и текстурированные деревья
Quaternius из общего каталога `web/src/graphics/models.ts` (CC0, модели хранятся локально). Канал-хранилище,
внешние изображения, платные модели и отдельный игровой бот не требуются.
Карта поддерживает масштабирование. В 3D камера вращается, клетки выбираются raycasting.
Список предприятий дублирует карту для клавиатуры и устройств без WebGL.

## Карта и персонажи

Игровая дорожка разделена на пронумерованные клетки с общими границами. Стрелки показывают
направление хода, старт и клетка текущего игрока выделены. Масштаб меняется кнопками
на основном поле; отдельного окна увеличенной карты нет. Список предприятий доступен.

В лобби, списке участников и на поле используется один `PlayerAvatar`: фото из существующего
`getTelegramUser().photo_url`, при отсутствии или ошибке загрузки — выбранный мужской/женский
портрет. Выбор не определяется по имени. У ботов фиксированные персонажи.

Косметические метаданные `appearances` привязаны к случайному ID места, доступны только
участникам комнаты и сохраняются в существующем JSONB состояния (без миграции). API принимает
фото только с `https://t.me/i/userpic/`; адрес не используется как подтверждение личности.
`POST /api/boardgame/rooms/{code}/appearance` обновляет только собственный портрет, включая
начатую партию. Повтор не меняет версию; обновление не затрагивает деньги, награды и срок хода.
Старые комнаты без метаданных загружаются с запасными портретами.

## Игровая монета

Dala (`◈`) — внутренняя монета партии. Баланс, цены, предложения и аренда показывают
её вместо символа тенге. В интерфейсе есть золотая монета с ромбом и подпись «Тек ойын ішінде».
Суммы и правила расчёта не меняются. Сохранённые журналы прежних партий приводятся к новому
обозначению при отображении через `gameText`; серверное состояние не переписывается.
Платежи и подписки кинотеатра используют свои реальные валюты.

## Правила партии

Фазы: бросок → покупка/пропуск либо оплата → завершение хода. Игрок может управлять
своими предприятиями во время своего хода. Два кубика по 1–6. На новом поле
дубль даёт ещё один бросок; три дубля подряд отправляют в тюрьму.
Выход: дубль либо 50 Dala. После третьей неудачи платёж обязателен; при нехватке
средств сначала погашается долг, затем выполняется выпавшее перемещение.
Выход дублем не даёт дополнительного броска. Бесплатная парковка не выдаёт деньги.
Проход через начало приносит доход сценария, отправка в тюрьму — нет.
Отказ от покупки оставляет предприятие в банке; аукциона нет.

Собранная цветовая группа удваивает базовую аренду. Для строительства все предприятия
группы должны принадлежать игроку и быть свободны от залога. Уровни увеличиваются
равномерно. Продажа строений также равномерная, за половину строительной цены.
Залог даёт половину цены предприятия; возврат — залог плюс 10% с округлением вверх.
Пока предприятие заложено, аренда за него не начисляется.

Если средств для платежа не хватает, игрок продаёт строения или закладывает
предприятия, затем подтверждает оплату. При банкротстве имущество передаётся кредитору,
либо возвращается банку, если долг перед банком. Суммы не становятся отрицательными.

Участники могут предлагать покупку, продажу, обмен предприятиями с доплатой,
встречную цену, отзыв и отказ. Передаётся незастроенное имущество без залога;
строения во всей цветовой группе должны быть проданы. Сделка атомарно передаёт
оба предприятия и монеты после согласия получателя актуального предложения.
Бот продаёт от 150% исходной цены и покупает до 2/3 исходной цены.
Предложение действует два круга и повторно проверяется при принятии: владелец,
строения, залог и средства покупателя. Предложение не резервирует деньги заранее.

Партия заканчивается по лимиту кругов либо при одном оставшемся участнике.
В режиме «Соңғы ойыншыға дейін» `round_limit=0`: круги не ограничены,
побеждает последний участник без банкротства. Счётчик показывает текущий круг / ∞.
Боты обрабатываются порциями до 128 шагов, без принудительного выбора победителя;
если остались одни боты, участники могут продолжить расчёт кнопкой на поле.
Капитал = деньги + исходная цена предприятий + стоимость строений − залоговая сумма.
При равенстве используется первоначальный порядок мест.

Первая победа человека в каждом сценарии даёт фиксированные 100/150/200 рейтинговых
очков. Таблица `board_awards` обеспечивает уникальность `(user_id, scenario_id)` даже
при победах в разных комнатах одновременно. Повторная победа не добавляет очки.
Гостевые партии в рейтинг не входят. Рейтинг опыта общий с языковой частью QazaqQuest;
суточный лимит 300 относится к языковым заданиям, награды за настольные сценарии — отдельные.

## Комнаты и синхронизация

- Комната имеет случайный код из десяти hex-символов. При создании выбирается
  закрытая комната для друзей либо открытая, видимая в списке свободных комнат.
- `GET /api/boardgame/rooms` возвращает до 30 открытых лобби со свободными местами.
  Запущенные, полные и закрытые комнаты скрыты. Присутствие хозяина обновляется
  при опросе комнаты; без него лобби исчезает из списка через две минуты.
- `GET /api/boardgame/rooms/mine` возвращает собственные незавершённые комнаты.
  Можно продолжить серверную партию с другого устройства под тем же Telegram-аккаунтом.
- Приглашение открывает форму с готовым кодом. Вручную можно вставить как код,
  так и полную ссылку. Лобби показывает приглашение, копирование ссылки/кода,
  свободные места и причину, по которой ещё нельзя начать.
- Вход допускается до старта; один Telegram-пользователь занимает одно место.
- Хост выбирает сценарий и ботов; люди подтверждают готовность. Смена сценария
  снимает готовность остальных людей.
- Выйдя из лобби, хост передаёт права следующему человеку. Начатая партия сохраняет состав.
- На ход человека даётся 180 секунд. После срока участник комнаты может запросить
  автоматическое завершение этого хода. Время проверяет сервер. Фонового таймера нет.
- При закрытом приложении партия сама не прокручивается: она ждёт действий участников.
- Запросы содержат номер версии комнаты. Под блокировкой строки принимается одно
  действие; повтор получает актуальное состояние без повторного списания/броска.
- Подделать деньги, позиции, кубики, владельца или награду через DTO нельзя.
  Кости и карточки на сервере выбираются через `secrets.randbelow`.
- Обновления используют HTTP long polling до 25 секунд и Redis Pub/Sub. Ожидание
  освобождает соединение PostgreSQL. Последняя версия в Redis закрывает гонку подписки.
  При недоступности Redis используется пауза перед повторным чтением, сохранение остаётся в БД.
- Нет серверного игрового цикла, WebSocket-кадров или запросов от анимаций.
  В 3D во время диалога и скрытой вкладки рендер остановлен; DPR и FPS ограничены.
  Короткая начатая анимация может завершиться под диалогом. Рисованный режим не
  держит графический цикл вне движения фишек; учитывается prefers-reduced-motion.

Ссылка-приглашение: `https://t.me/qazaqcinema_bot?startapp=quest_room_<КОД>`.
Требуется настроенная Main Mini App на существующий домен.
Параметр запуска открывает нужную комнату, но не является авторизацией.
В API комнаты видны игровые имена и случайные ID мест; внутреннее соответствие
Telegram ID → место не отдаётся. Копирование ссылки не отправляет сообщения автоматически.

## Конструктор

Новый сценарий добавляется записью в `scenarios`, например:

```json
{
  "id": "almaty_evening",
  "board": "almaty",
  "name": "Алматы · Кешкі партия",
  "story": "Қысқа партия: кәсіптеріңді тиімді таңда.",
  "round_limit": 10,
  "starting_cash": 1300,
  "salary": 160,
  "tax_multiplier": 1,
  "event_multiplier": 1,
  "reward": 100
}
```

У поля задаются имя, палитра, клетки и один из готовых 3D-стилей:
`almaty`, `astana`, `turkistan`, `steppe`. Размер — 16–40 клеток, кратно четырём.
Клетки поддерживают `start`, `property`, `station`, `tax`, `chance`, `rest`.
Поля, названия, цены, аренда, группы, длина партии и карточки задаются данными.
Для совершенно новой механики клетки нужен обработчик правил и визуальный модуль;
повторять существующие сценарии в коде не нужно. Визуальный редактор контента пока не добавлен.

```bash
.venv/bin/python -m app.tools.validate_boardgame
.venv/bin/python -m app.tools.validate_boardgame --catalog path/to/catalog.json
```

Проверяются уникальность ID, ссылки сценариев, размеры полей, палитры, группы,
цены, аренда, параметры сценария и безопасные перемещения карточек. Проверка не
доказывает соревновательный баланс; его нужно оценивать плейтестами.
Не менять смысл существующего `scenario_id`, если за него уже выдавались награды.
При несовместимых правилах или структуре набора поднять `version`: старую партию
нельзя продолжить по другим правилам. Каталог версии 3 содержит архив версии 2
в `legacy_catalogs`; отдельная копия — `catalog-v2.json`. Начатые партии и старые
лобби выбирают архив по версии или ID сценария и продолжаются на поле из 24 клеток.
Новые сценарии имеют ID с `classic`; награды старых сценариев не меняют смысл.

## Слои и проверки

- `app/domain/boardgame/` — модели, чистые правила, проверка конструктора.
- `app/application/ports/boardgame.py` и `services/boardgame_service.py` — контракты и сценарии.
- `app/infrastructure/db/repositories/boardgame.py` — транзакции, блокировки, награды.
- `app/infrastructure/cache/boardgame.py` — генератор случайности и сигналы Redis.
- `app/api/routers/boardgame.py` — HTTP/авторизация/DTO.
- `web/src/boardgame/rules.ts` — клиентские правила тренировки и расчёт подсказок.
- `web/src/boardgame/world.ts` — дополнительный 3D-режим.
- `web/src/boardgame/components/IllustratedBoard.tsx` — интерактивные SVG-клетки и фишки;
  `components/illustration/MapGarden.tsx` — расстановка объектов центрального парка;
  `components/illustration/ParkDecoration.tsx` — объекты из общего атласа 4×2;
  `components/illustration/BuildingMiniature.tsx` — здания, улицы и транспорт; остальные компоненты — экраны и карточки.

Контрактные тесты сравнивают полный результат партии для всех 6 сценариев между
Python и TypeScript. Отдельно проверяются покупки, аренда, цветовые группы, залоги,
долги, сделки, банкротство, авторизация, конкурентный вход и однократные награды.

```bash
.venv/bin/ruff check app tests
.venv/bin/mypy app
# Только изолированная БД *_test, согласно tests/conftest.py:
.venv/bin/pytest
npm test --prefix web
npm run build --prefix web
```

Выпуск — через существующий `./start.sh prod` после резервной копии.
Миграция `20261111_boardgame.py` создаёт `board_rooms` и `board_awards`.
Кнопки бота и рейтинг используют имеющуюся интеграцию QazaqQuest; публикация в канал
остаётся выключенной при `QUEST_CHANNEL_ID=0`. Проверку на реальных телефонах,
производительность VPS и доставку приглашений через Telegram проводят после деплоя.

## Проверка совместной игры — 11 ноября 2026

Локальный стенд: настоящий API, отдельные PostgreSQL и Redis, четыре фиктивных
профиля с HMAC-входом и независимыми браузерными хранилищами. Боевой бот и БД не использовались.

Проверены создание комнаты, вход по коду, готовность четырёх участников, запуск,
кубики, покупка и передача хода. Изменения приходят другим участникам без перезагрузки.
После обновления страницы сохраняются комната, состав, деньги и текущий ход.
Принудительно отозванная тестовая сессия восстанавливается через initData.

Отдельная полная HTTP-партия четырёх пользователей завершена после 109 команд
(финальная версия комнаты 117): все четыре клиента получили одинаковый результат.
Одновременные команды с одной версией применяются один раз; остальные получают `stale`.
Ожидающие запросы четырёх участников разбужены реальным Redis Pub/Sub.

Исправлены обрыв long-poll раньше серверного срока ожидания, игнорирование отмены
запроса при выходе и уход крестика за край при прокрутке. Заголовок модального окна
закреплён, закрытие имеет область 44×44, прокрутка фона заблокирована при открытом окне.
Проверены закрытие крестиком и Escape, отсутствие горизонтального переполнения на
1280×720 и восстановление связи после ожидания. Карта мемоизирована: обновление
секундного таймера не вызывает её повторную отрисовку.

Регрессии: 691 Python-тест без пропусков, 16 клиентских тестов, ruff, mypy и production-сборка.
Постоянные проверки четырёх игроков — `tests/test_boardgame_repositories.py`,
таймаутов и отмены — `web/tests/transport.test.mjs`.

Готовая BroadcastQueue предназначена для фоновых Telegram-рассылок. Игровые действия
сохраняются транзакцией с блокировкой комнаты; Redis доставляет уведомление о новой
версии, а пропущенное уведомление восстанавливается чтением состояния из PostgreSQL.
Маркер версии в Redis только возрастает: `WATCH/MULTI` атомарно сравнивает и
записывает новую версию вместе с публикацией. Запоздалые события не понижают
маркер и не заставляют клиента ждать следующего хода. Регрессии порядка событий,
конкурентной публикации, подписки и отказа Redis — `tests/test_boardgame_events.py`.
Дополнительно проверены 50 запоздалых конкурентных публикаций на настоящей Redis.

Это не замер FPS и не нагрузочный тест VPS. В этой сессии инструмент изменения
viewport не изменил фактические 1280×720; новый мобильный размер не подтверждён.
Реальные iOS/Android Telegram WebView, слабые устройства, мобильная сеть и доставка
приглашений через Telegram остаются отдельной проверкой после развёртывания.

Парковые декорации загружаются из `web/public/boardgame/art/park-props-v1.webp`.
Атлас создан встроенным image_gen, [промпт сохранён рядом](web/public/boardgame/art/park-props-prompt.md).
Слои объектов отсортированы по глубине; декорации не перехватывают нажатия на карту.
Лёгкое покачивание листвы и рябь воды работают через CSS и выключаются
при `prefers-reduced-motion: reduce`.

## История и рейтинг настольных партий

Клиент рисует карту и анимацию. В сетевой игре сервер проверяет команды,
бросает кубики, сохраняет состояние, завершение и результаты. Локальная тренировка
не импортируется на сервер, в историю или рейтинг.

`board_results` хранит результат каждой завершённой сетевой партии для каждого
человека: код, сценарий, карту, время, круги, победителя, капитал и исход.
Результаты, состояние комнаты и награда сохраняются в одной транзакции.
Первичный ключ `(code, user_id)` защищает от повторного учёта.

- `GET /api/boardgame/history?offset=0` — личная история, по 20 результатов.
- `GET /api/boardgame/ranking` — 50 лидеров и собственная позиция. Порядок:
  число побед, доля побед, затем стабильный ID. В интерфейсе показаны победы,
  сыгранные партии и процент побед. Telegram ID в ответ не передаётся.
- История доступна через «Менің партияларым», отдельный рейтинг — через кубок.
  Опыт аула по-прежнему имеет собственный рейтинг.

При деплое применить миграцию `20261111_board_results.py` (`alembic upgrade head`)
перед запуском обновлённого API. Старые завершённые партии автоматически в новую
таблицу не переносятся. Открытость и портреты лежат в JSONB состояния комнат;
старые комнаты по умолчанию остаются закрытыми.

Мобильное поле идёт отдельным блоком после управления без фона. Под полем —
лента имущества, пять компактных карточек одновременно; остальные прокручиваются
по горизонтали. Нажатие открывает управление выбранным имуществом.

## Первые три партии и подписка на канал

Первые три старта сетевых партий доступны без подписки. Счётчик берётся из
серверных комнат с начатым Match; лобби и повтор команды не расходуют попытки.
Перед следующим стартом каждый человек должен быть подписан на канал из
`BOT_PUBLIC_CHANNEL_ID` / `BOT_PUBLIC_CHANNEL_USERNAME`. Используется существующий
`ChannelMembership`: отказ не кэшируется, проверка после подписки доступна сразу;
положительный ответ и сбои Telegram обрабатываются по общей политике этого порта.
Без настроенного канала ограничение на сервере не включается.

Одновременные старты сериализуются блокировками строк пользователей в стабильном
порядке до commit комнаты. Проверяются все люди в составе, не только хозяин.
Отказ возвращает `channel_required` и случайные ID заблокированных мест.
Уже начатую партию можно продолжать независимо от подписки.
`GET /api/boardgame/access` возвращает только собственный доступ и адрес канала.

Гостевая тренировка считает три старта отдельно в localStorage. Это локальное
ограничение интерфейса, не защита от очистки хранилища или другого устройства;
после трёх стартов предлагается Telegram. Гостевые попытки не переносятся на
серверный аккаунт без подтверждённой личности.

## Публичная страница игры

`/games` — SSR-страница без авторизации, готовый HTML без выполнения JavaScript:
описание на казахском и русском, FAQ, иллюстрации, canonical, Open Graph,
Twitter Card и schema.org/VideoGame. Основная кнопка ведёт в текущего Telegram-бота
с `startapp=quest`, вторая — в браузерную тренировку `/quest`.
Страница включена в sitemap, доступна robots.txt и связана с каталогом и игрой.
Реальный домен canonical берётся из `PUBLIC_ORIGIN`. Caddy направляет `/games`
в API до SPA; в dev необходим локальный API на `API_TARGET`.
Индексация и позиции в Google зависят от обхода поисковиком после публикации.
