# QazaqQuest — игровой модуль

Основной экран `/quest` — настольная игра [«Дала дәулеті»](BOARDGAME.md).
Языковая 3D-глава ниже доступна через «Менің ауылым»; её прогресс хранится отдельно.


Первая играбельная глава: личный аул и три духа в 3D-алқапе. Игрок исследует
окрестности, отвечает на вопросы по казахскому языку, получает опыт и материалы,
строит юрту, колодец и мастерскую. У каждого здания три уровня.

Визуальное окружение использует текстурированные деревья Quaternius, небольшие детали
Kenney и собственный газон: текстура с грунтовыми тропами и объёмные травинки с ветром.
Оба сторонних набора — CC0; модели и лицензии хранятся локально в `web/public/models/`.
Текстуры деревьев уменьшены до 512px, повторения отрисовываются через InstancedMesh.
При ошибке загрузки деревьев остаётся геометрическое окружение. Низкое качество
уменьшает число травинок, DPR и отключает тени.

Общий UI kit: `web/src/ui-kit/README.md`; интерактивная витрина — `/ui-kit`.

## Запуск

```bash
cd web
npm ci
npm run dev
```

Открыть `http://localhost:5173/quest` и выбрать «Менің ауылым». В обычном браузере работает гостевая тренировка:
прогресс в localStorage, без API и участия в рейтинге. Ничего из этой тренировки не
импортируется в серверный кошелёк. Для тестов фронтенда нужен Node 22.18+ (`npm test`);
production build совместим с существующим Node 20 Docker-образом.

В Telegram используется существующая авторизация QazaqCinema: HMAC-проверенный
`initData` → серверная сессия. Поддерживаются:

- `https://t.me/qazaqcinema_bot?startapp=quest` — прямая ссылка для канала;
- `/quest` или `/start quest` в личном чате с ботом;
- кнопка с юртой в шапке кинотеатра;
- `/quest` и `?game=quest` на основном домене.

Для ссылки `startapp` в BotFather должна быть настроена Main Mini App на существующий
домен кинотеатра. При переходе кинотеатр ↔ игра роутинг остаётся клиентским: SDK и
Telegram initData не теряются. Параметры запуска используются только для навигации,
не для определения личности и начисления наград.

## Правила

- Первый вход: пустой аул. Духи открываются последовательно: орман → бұлақ → аспан.
- Каждый дух выдаёт три вопроса из своего пула. Набор стабилен для игрока в течение дня.
- Правильный ответ с первой попытки: 30 очков; после ошибки: 10; завершение: ещё 10.
- Максимум 100 очков за духа, 300 в сутки. Повторный запуск завершённого испытания
  возвращает сохранённое состояние, без повторного начисления.
- Завершение испытания даёт 25 дерева и 15 камня. Расход материалов не отнимает XP.
- Опыт хранится постоянно, уровень = `1 + total_xp // 300`. Недельный рейтинг использует
  отдельный накопитель; начало новой недели не обнуляет опыт и аул.
- День и неделя сменяются по Asia/Almaty; неделя начинается в понедельник 00:00.
- При равных очках используется стабильный порядок `user_id ASC`; личные Telegram ID
  в JSON рейтинга и в публикации не раскрываются. Имена — игровые псевдонимы.

Стоимость строительства (дерево / камень):

| Здание | 1 уровень | 2 уровень | 3 уровень |
|---|---:|---:|---:|
| Юрта | 25 / 10 | 45 / 25 | 70 / 40 |
| Колодец | 20 / 20 | 40 / 35 | 60 / 50 |
| Мастерская | 35 / 15 | 55 / 30 | 80 / 45 |

## Границы и нагрузка

- Three.js, геометрия, движение, поиск пути A*, анимации и эффекты исполняются на клиенте.
- Нет WebSocket, серверного игрового цикла, запросов на каждый кадр и API-опроса рейтинга.
- Один сеанс с тремя идеально пройденными испытаниями: авторизация, чтение прогресса,
  три старта и девять ответов. Строительство и открытие рейтинга добавляют запросы
  только по действию игрока. Повторные входы восстанавливают прогресс с сервера.
- Three.js и игра загружаются отдельно от кинотеатра. Caddy сжимает статику gzip и
  кэширует файлы с хешем на год. При необходимости `/assets/*` можно раздавать через CDN;
  персональные `/api/*` кэшировать публично нельзя.
- Деревья и цветы используют instancing; ограничены DPR и частота кадров.
  Во время модального окна и в скрытой вкладке рендеринг остановлен. Есть режим
  экономичной графики и обработка потери WebGL-контекста.
- Топ-10 кэшируется в Redis на 300 секунд; личное место считается при открытии рейтинга.
  Индексы: `(total_xp DESC, user_id)` и `(week, points DESC, user_id)`.

Сервер проверяет владение испытанием, порядок вопросов, варианты ответа, попытки,
суточный лимит, стоимость и порядок улучшений. Он **не симулирует движение** и не
доказывает, что игрок физически дошёл до святилища. Эта защита предотвращает подмену
суммы очков и повторные награды, но не автоматизированное решение языковых заданий.
Денежные призы и соревновательные механики с ценными наградами потребуют отдельной защиты.

Рейтинговые ответы и строительство требуют подключения. Потерявший ответ клиент
может повторить тот же запрос: состояние восстанавливается без второй награды или
второго списания. Гостевая тренировка после загрузки работает без сервера; первое
открытие и перезагрузка всё ещё требуют загрузки приложения (Service Worker не добавлен).

## Слои

| Ответственность | Код |
|---|---|
| Контент, начисление, календарные границы, строительство | `app/domain/quest/` |
| Сценарии испытаний, рейтинга и публикаций | `app/application/services/quest*_service.py` |
| Контракты хранилища, кэша и публикации | `app/application/ports/quest.py` |
| Транзакции, блокировки, агрегаты, журнал доставки | `app/infrastructure/db/repositories/quest.py` |
| Redis и Telegram | `app/infrastructure/cache/quest.py`, `app/infrastructure/telegram/quest.py` |
| HTTP и DTO | `app/api/routers/quest.py`, `app/api/schemas/quest.py` |
| Рендеринг, геометрия, ввод, поиск пути | `web/src/quest/world/` |
| HTTP-клиент и изолированная тренировка | `web/src/quest/gateway.ts`, `practice.ts` |

Начисление происходит в транзакции под `SELECT FOR UPDATE` по испытанию. Уникальность
`(user_id, quest_id, day)` задаётся БД. Последний ответ, опыт, материалы и недельный
результат коммитятся вместе. Строительство блокирует кошелёк игрока; `target_level`
служит ключом идемпотентности. Входные DTO не принимают очки, материалы и чужой user_id.

## HTTP API

Все запросы требуют существующий `Authorization` QazaqCinema.

| Метод | Путь | Тело / назначение |
|---|---|---|
| GET | `/api/quest/progress` | Кошелёк, опыт, здания, завершённые испытания |
| POST | `/api/quest/runs` | `{ "quest_id": "forest" }` |
| POST | `/api/quest/runs/{uuid}/answer` | `{ "question_index": 0, "answer": "Орман" }` |
| POST | `/api/quest/build` | `{ "building_id": "yurt", "target_level": 1 }` |
| GET | `/api/quest/ranking?period=week` | Топ-10 и собственное место; также `period=all` |

Неизвестное/закрытое испытание: `409 quest_locked`; истёкший день:
`409 quest_run_expired`; недостаточно ресурсов: `409 quest_not_enough_materials`;
чужое испытание: `404 quest_run_not_found`; недоступная БД: `503 quest_unavailable`.
Rate-limit привязан к подтверждённому игроку: чтение/старт/строительство 30 в минуту,
ответы 60, рейтинг 12. Redis деградирует fail-open, транзакционная защита остаётся в БД.

## Выпуск на существующий VPS

1. Сделать существующий backup по `DEPLOY.md`.
2. Обновить исходники. Запустить `./start.sh prod`: штатный migrate применит
   `20261110_qazaqquest.py`, затем обновятся API, бот и статика.
3. Проверить `/quest`, вход через Telegram, сохранение после перезапуска и `/quest` в боте.
4. Для публикаций задать в `.env.prod` `QUEST_CHANNEL_ID` — ID нужного публичного канала
   (можно тот же, что `BOT_PUBLIC_CHANNEL_ID`). Бот должен иметь права публикации и
   редактирования. `QUEST_CHANNEL_ID=0` отключает публикации.
5. Перезапустить через `./start.sh prod`. По умолчанию рейтинг обновляется ежечасно в
   `:15` (`QUEST_POST_MINUTE`). При пустом рейтинге пост не создаётся.

В течение недели редактируется один пост топ-10. Первый запуск расписания в новой
неделе публикует отдельный итог прошлой недели и начинает новый текущий пост. Публикации
запускает только процесс бота, не API. Автоматического закрепления нет.

`quest_channel_posts` хранит резервирование **до** отправки в Telegram. Если процесс
остановился между отправкой и сохранением message_id, повторная отправка заблокирована,
а лог сообщает о неопределённой доставке. Оператор должен сверить канал: записать ID
реально доставленного сообщения либо удалить только соответствующую резервирующую
строку, если сообщения точно нет. Это сознательная защита от повторных публичных постов;
Telegram sendMessage не предоставляет ключ идемпотентности.

## Проверка

```bash
.venv/bin/ruff check app tests
.venv/bin/mypy app
# Только отдельная БД с именем *_test, согласно tests/conftest.py:
.venv/bin/pytest
npm test --prefix web
npm run build --prefix web
npm audit --prefix web
```

Тесты покрывают календарные границы, порядок заданий, лимиты, повторные ответы,
параллельное начисление и строительство, недельный/общий рейтинг, HTTP-контракт,
отказ авторизации, кэш и неопределённую доставку поста. Нагрузочную ёмкость и FPS
нужно измерять на целевом VPS и реальных телефонах: локальный прогон не задаёт число
поддерживаемых одновременных игроков.


## Первые шаги и получение ресурсов

При первом старте аула открывается короткое обучение: три ответа → 25 дерева и
15 камня → первая юрта за 25 дерева и 10 камня. До первой постройки на экране
остаётся следующий шаг; после награды карточка юрты выделяется и попадает в
видимую область окна строительства.

Кнопка заданий на основном экране и «Ресурс жинау» в строительстве открывают
дневник: доступные задания запускаются сразу, без поиска духов в 3D-мире.
Заблокированные задания называют предыдущего духа, выполненные — время следующей
награды (00:00 Алматы). Начисление материалов происходит после третьего ответа,
даже если игрок ошибался. Повторное открытие награды не выдаёт её заново.
Дефицит стройматериалов показан отдельно для дерева и камня вместе с числом
необходимых заданий. В ауыле нет отдельной валюты: XP используется для уровня
и рейтинга; монеты настольной игры не являются материалами аула.

Проверка пути первого игрока и расчётов: `web/tests/quest_resources.test.mjs`.
